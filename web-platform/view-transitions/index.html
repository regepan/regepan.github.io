DOMの変化を滑らかにつなぐ View Transition API

更新前と更新後の画面をブラウザが捉え、自然な切り替えを生成します。複製したDOMの位置合わせや後片付けは不要です。

Baseline 2025対応状況：2026年9月1日確認

View Transition APIは、ある画面状態から次の状態への変化をアニメーションでつなぐ仕組みです。この記事では、1ページ内でDOMを書き換える同一ドキュメントのView Transitionを扱います。

この記事で扱う同一ドキュメントのdocument.startViewTransition()の対応範囲です。ページ間のView Transitionは別の機能で、対応バージョンが異なります。

レイアウトを切り替える

グリッド表示とリスト表示を切り替えてください。それぞれのカードに同じview-transition-nameを対応付けることで、カードが新しい位置へ移動するように見えます。

Live demo単独ページで開く ↗

最小コード

function updateView() {
  document.body.classList.toggle('compact');
}

if (document.startViewTransition) {
  document.startViewTransition(updateView);
} else {
  updateView();
}

画面を変える処理をdocument.startViewTransition()へ渡します。ブラウザは更新前の表示を撮影し、コールバックを実行したあと、更新後の表示との間をアニメーションします。

要素ごとの動きを作る

初期状態ではページ全体が1枚の画像として切り替わります。特定の要素を個別に動かしたい場合は、更新前後で共通する一意なview-transition-nameを指定します。

.card-orbit {
  view-transition-name: card-orbit;
}

::view-transition-group(card-orbit) {
  animation-duration: 420ms;
  animation-timing-function: cubic-bezier(.2, .8, .2, 1);
}

ブラウザは同名の古い要素と新しい要素を対応付けます。同じ名前を同時に複数の表示要素へ付けると遷移が作れないため、名前は一意にします。

アニメーションが失敗しても更新は残る

View Transitionは視覚効果です。アニメーションが開始できない場合やスキップされた場合でも、DOM更新後の状態は表示されます。アプリの本来の処理をアニメーションへ依存させないことが大切です。

アクセシビリティの注意

  • prefers-reduced-motion: reduceではトランジションを省略し、状態だけを即座に更新します。
  • 切り替え後もキーボードフォーカスが予測できる位置に残るようにします。
  • アニメーションだけで状態を伝えず、選択中ボタンのaria-pressedやテキストも更新します。
  • 大きな移動や点滅を避け、内容の把握を助ける範囲で使います。

未対応ブラウザでは

document.startViewTransitionの存在を確認し、未対応なら同じ更新関数を直接呼び出します。この設計ならポリフィルがなくても機能は失われず、アニメーションだけが省略されます。

const reduceMotion = matchMedia(
  '(prefers-reduced-motion: reduce)'
).matches;

if (!document.startViewTransition || reduceMotion) {
  updateView();
  return;
}

document.startViewTransition(updateView);

設計のコツ：最初にアニメーションなしで正しく動く更新処理を作り、その関数をView Transitionで包むと、フォールバックも自然に完成します。
